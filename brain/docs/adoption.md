# 自分の環境へのコピー

## 読むだけ

公開版には架空案件しかありません。READMEから関連ファイルを辿って構造を確認できます。
コードを実行しなくても、ルール、記録形式、サンプルの関係を読むことはできます。

## 自分の記録を保存して使う

再利用について所有者の許可を得たうえで、公開版のファイルを利用者が管理する非公開の新しい作業場所へコピーします。
個人記録を公開forkへ書き足さないよう、保存先の公開範囲とGitのremoteを先に確認します。
ZIPから始める場合は新しいフォルダでgit initを実行し、自分が用意した保存先だけをremoteへ設定します。
公開版のGit履歴や元の個人用リポジトリを日常作業の前提にしません。

1. READMEの検査を実行する。
2. 架空のsample-reportを読んで、正本と成果物の関係を確認する。
3. initializerで自分の案件を別名で作り、goalとProjectの現在地を記入する。
4. 自分のAIに入口の指示とファイルアクセスを与える。
5. 架空の入力で、保存、作業終了、新しい会話での再開を確かめる。
6. 権限と機密性を確認したうえで、実際の記録を非公開の作業場所へ追加する。

sample-reportはそのまま保持しても構いません。自分用コピーで不要になれば、Project・案件・記録へのリンクを一緒に確認して除きます。
原本の個人用環境の承認設定、アカウント、常設タスク、秘密情報はこのコピーに含みません。
新しい利用者は自分の権限設定を明示してください。

## GitHubの自動検査

.github/workflows/validate.ymlは検査専用です。contents: readで実行し、生成物のcommit・pushをしません。
NOWを変えるときはローカルで再生成して、本人の承認範囲でcommitします。
公開版を更新するときも個人記録を逆流させず、共通ファイルの差分だけを確認します。
